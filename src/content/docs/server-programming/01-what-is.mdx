# Programacion del Lado del Servidor

La programacion del lado del servidor (Server-Side Programming) es el proceso de crear aplicaciones que se ejecutan en un servidor web y generan respuestas dinamicas para los clientes.

```d2 pad=30
shape: sequence_diagram
client: CLIENTE
server: SERVIDOR

database: BASE DE DATOS

client->server: 1. Peticion HTTP (GET /usuarios)
server->database: 2. Consulta SQL

database->server: 3. Resultados
server->server: 4. Procesar datos (PHP)
server->client: 5. Respuesta HTML/JSON

```

## Desarrollo Web Backend

Las aplicaciones web modernas requieren funcionalidades complejas que solo pueden ejecutarse en el servidor:

<Steps>
1. **Autenticacion de usuarios**: Validacion de credenciales, gestion de sesiones y tokens de seguridad.
2. **Almacenamiento de datos**: Persistencia en bases de datos, cache y sistemas de archivos.
3. **Procesamiento de negocio**: Reglas de negocio, calculos, integraciones con otros servicios.
4. **Seguridad**: Encriptacion, validacion de datos, proteccion contra ataques (SQL Injection, XSS).
5. **Comunicaciones**: Envio de correos, notificaciones push, WebSockets.
</Steps>

## El Servidor Web

Un servidor web es un programa que escucha peticiones HTTP y responde con contenido. Los mas utilizados en el ecosistema PHP son:

| Servidor | Caracteristicas | Uso Principal |
|----------|----------------|---------------|
| **Apache HTTP Server** | Flexible, modular, archivo `.htaccess` | Hosting compartido, proyectos PHP tradicionales |
| **Nginx** | Alto rendimiento, bajo consumo de recursos, proxy inverso | Aplicaciones de alta concurrencia, microservicios |
| **Caddy** | Configuracion automatica HTTPS, moderno | Desarrollo local, despliegues simples |
| **IIS** | Integrado con Windows, soporte .NET | Entornos empresariales Windows |

:::tip[Apache vs Nginx]
**Apache** utiliza un enfoque basado en procesos/threads con configuracion por directorio (`.htaccess`), ideal para hosting compartido. **Nginx** usa arquitectura asincrona orientada a eventos, manejando mas conexiones simultaneas con menos memoria. Para aplicaciones Laravel modernas, Nginx es generalmente preferido en produccion.
:::

## Stack Tecnologico Backend

Un stack backend tipico incluye multiples componentes que trabajan en conjunto:

<Card title="Componentes del Stack Backend" icon="information">
- **Servidor Web**: Apache2 o Nginx - recibe y responde peticiones HTTP
- **Interprete PHP**: Ejecuta el codigo PHP y genera HTML dinamico
- **Base de Datos**: MySQL/MariaDB, PostgreSQL, SQLite - almacenamiento persistente
- **Cache**: Redis o Memcached - almacenamiento en memoria para rendimiento
- **Gestor de Dependencias**: Composer - manejo de librerias PHP
- **Control de Versiones**: Git - seguimiento de cambios en el codigo
</Card>

## Entornos de Desarrollo Integrados

Configurar manualmente cada componente del stack puede ser complejo. Por eso existen paquetes que incluyen todo lo necesario:

| Paquete | Sistema Operativo | Componentes | Ideal Para |
|---------|------------------|-------------|------------|
| **XAMPP** | Windows, Linux, macOS | Apache, MariaDB, PHP, Perl | Principiantes, multiplataforma |
| **Laragon** | Windows | Apache/Nginx, MySQL, PHP, Redis, Node.js | Desarrollo Windows (usado en este curso) |
| **WAMP** | Windows | Apache, MySQL, PHP | Solo Windows |
| **MAMP** | macOS, Windows | Apache/Nginx, MySQL, PHP | Usuarios Mac |
| **LAMP** | Linux | Apache, MySQL, PHP | Servidores Linux |

:::note[Sobre Laragon]
En este curso utilizamos **Laragon** por su facilidad de uso en Windows, soporte para multiples versiones de PHP, configuracion intuitiva y herramientas integradas como SSL automatico y creacion rapida de proyectos Laravel.
:::

## Arquitectura Cliente-Servidor

El modelo cliente-servidor es la base de la web moderna:

```
+-----------+        HTTP Request        +-------------+
|           | -------------------------> |             |
|  Cliente  |                            |  Servidor   |
| (Browser) | <------------------------- |   (PHP)     |
|           |      HTML/JSON/CSS/JS      |             |
+-----------+                            +-------------+
                                                  |
                                                  v
                                           +-------------+
                                           |   MySQL     |
                                           |  (Datos)    |
                                           +-------------+
```

1. El **cliente** (navegador) envia una peticion HTTP al servidor
2. El **servidor web** recibe la peticion y la pasa al interprete PHP
3. **PHP** ejecuta la logica de la aplicacion, consultando la base de datos si es necesario
4. PHP genera una respuesta (tipicamente HTML o JSON)
5. El servidor web envia la respuesta al cliente
6. El cliente renderiza la respuesta para el usuario
